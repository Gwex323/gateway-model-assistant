# 网关模型助手

Windows 桌面工具：从 OpenAI 兼容或 Anthropic 网关获取模型列表，选择模型后批量导入 WorkBuddy、Trae 或 TraeWork CN。OpenAI 模式可选择多个导入目标；Anthropic 原生模式目前仅支持 TraeWork CN。

## 下载与运行

在 GitHub Releases 下载最新 Windows 便携版 ZIP，解压完整文件夹后运行 `网关模型助手.exe`，请保留同目录的 `_internal` 文件夹。需要 Windows 10/11；程序未数字签名，请勿为了运行它关闭系统安全防护。

使用流程：填写 Base URL 和 API Key，获取模型，选择导入目标及模型，检查预览后确认导入。导入前请按提示退出目标应用；已有同 URL 模型可选择“保留已有”或“覆盖已有”。工具不会读取已保存在其他应用中的 API Key；导入时会写入目标应用的原生配置，并在写入前创建安全备份。不要把客户端配置或备份上传到公开仓库。

从源码运行（Windows、Python 3.10+，Tkinter）：

```powershell
python app.py
python -m unittest discover -s tests -q
```

构建 Windows 便携版：在 `.build-venv` 中安装 `requirements-build.txt` 后执行 `./build_windows.ps1`。导入适配的范围和限制见下文以及 `ADAPTER_NOTES.md`。目标应用图标的归属见 `assets/TARGET_ICONS.md`。

## 使用步骤

1. **选择协议并连接网关**：选择 OpenAI 或 Anthropic，手动填写 Base URL 与 API Key。工具不读取或复用任何应用中保存的连接或凭据。切换协议后必须重新获取模型。
2. **获取模型列表**：只发送模型列表 GET 请求，不会调用聊天或付费生成端点。OpenAI 默认使用 Bearer；Anthropic 按连接选择 Bearer 或 `x-api-key`，并携带 `anthropic-version`，自动读取分页。根地址、已知服务商地址和兼容子路径按连接规则解析；已有版本路径保留。
3. **选择模型**：点击模型行勾选，支持搜索，搜索框右侧的“全选”只选择当前搜索结果，不取消其他已选模型；预览会列出全部已选模型。
4. **选择导入目标**：OpenAI 模式下 WorkBuddy、Trae、TraeWork CN 都是独立开关，可单选或多选；Anthropic 模式会自动只保留 TraeWork CN。
5. **确认能力**：按实际能力设置本批模型是否支持工具调用、图片输入及推理标记。WorkBuddy 新建或覆盖模型时工具调用默认开启，手动选择“关闭”优先；图片输入默认自动识别。选择“保留已有”不会改动现有模型配置。
6. **核对自动窗口**：模型列表会逐项显示“最大输入 Token”和“最大输出 Token”。工具优先读取上游明确提供的输入/输出字段；若只有总上下文，则在输出上限已知时自动扣除输出部分。没有可靠元数据时显示“未识别”，不按模型名称或公共数据库猜测。未识别的新模型不声明该值；覆盖已有模型时保留应用中的原值。
7. **选择已有模型策略并预览**：对于目标应用中同一 Base URL、同一协议/provider、同一模型 ID 的记录，可选择“保留已有”或“覆盖已有”。其他 URL 或其他协议下的同名模型、WorkBuddy 的其他服务商/协议条目以及 Trae 的内置模型始终保留，不会被改绑。
8. **退出客户端**：完全退出将要写入的 WorkBuddy、Trae 或 TraeWork CN，包括系统托盘与后台进程。工具不会强制结束应用。
9. **确认导入**：WorkBuddy 与普通 Trae 会检查预览快照并在写入前创建加密备份；TraeWork CN 会由工具临时启动、通过客户端服务持久化并正常重启。
10. **重新打开客户端**：核对模型选择器。真实模型调用需要你另行验证，可能产生网关费用；本工具不自动执行这些调用。

## 安全与恢复

- 工具不保存 API Key 到自己的配置、日志或导出清单。不包含账户、真实密钥或个人配置文件；测试仅使用明确标注的虚构密钥。
- **客户端原生配置会保存 API Key**。为了兼容，导入 Trae 后密钥会进入 Trae 本地缓存，WorkBuddy 也会在其原生模型文件中明文保存；工具不会把密钥写入自己的配置、日志或无密钥清单。工具写入前对临时文件应用 Windows ACL，仅授权当前账户和 SYSTEM。
- 备份位于 WorkBuddy 配置目录下的 `gateway-model-assistant-backups`，使用 Windows DPAPI 加密，只能由创建它的 Windows 用户解密。不要把它当成跨电脑备份或迁移文件。文件名含 UTC 时间。
- 应用内不再提供恢复按钮；底层恢复工具仍保留。WorkBuddy 或普通 Trae 的本地备份应在确认目标客户端完全退出后恢复；Trae 备份同时包含数据库、WAL 和 SHM 文件。SOLO CN 的服务端持久化模型不通过本地备份恢复。
- 备份不会自动过期或自动删除。应用原有备份或原有日志不在本工具管理范围内。
- 公网只接受 HTTPS；本机回环 HTTP 可直接使用。手动填写私有网络 IP 的 HTTP 地址时，获取模型前必须确认 API Key 和请求内容可能被同一局域网中的设备读取；公网 HTTP 始终拒绝。禁止地址中携带账号、查询参数或片段；不跟随重定向。
- 暂不使用系统/环境代理，不支持强制代理的企业网络。不跳过 TLS 证书验证。
- WorkBuddy 模型配置限制为 4 MiB；Trae 单个数据库文件限制为 64 MiB。未知或损坏的配置结构、重复 ID 都会停止，不会清空重建。
- 不抢占/删除现有应用锁。若崩溃后遗留锁，请先确认 WorkBuddy 与工具均已退出，备份配置，再由人工诊断；不要盲目删除。

## Trae 适配边界

- **普通 Trae**：仅修改 `ItemTable` 中以 `AI.agent.model.model_list_map` 结尾的模型列表；只新增或更新 OpenAI 兼容的个人自定义模型，内置模型不重定向。这仍是本地缓存适配。
- **TraeWork CN**：不再写 SQLite 模型缓存。OpenAI 模式写入 `custom_openai_compatible` 与 `/chat/completions`；Anthropic 模式写入 `custom_anthropic_compatible` 与 `/messages`（规范化后的完整地址为 `/v1/messages`）。写入后在同一客户端会话中刷新 `model_list` 验证。
- **已有模型处理**：保留/覆盖仅匹配同一规范化 Base URL、同一 provider 和同一模型 ID；不同 URL 或不同协议下的同名模型不会被重定向。
- **上下文窗口字段**：OpenAI 模式从 `/models` 的每条记录读取常见 snake_case、camelCase 及允许的嵌套字段；Anthropic 模式明确读取 `max_input_tokens` 与 `max_tokens`。WorkBuddy 写入 `maxInputTokens` / `maxOutputTokens`；普通 Trae 与 TraeWork CN 分别映射为 `prompt_max_tokens` / `max_tokens`。
- 客户端内部接口并非公开稳定 API，升级后如接口变化，工具会停止并显示安全错误，不回退为“写缓存即成功”。
